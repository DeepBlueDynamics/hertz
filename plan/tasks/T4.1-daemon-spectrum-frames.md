# T4.1 — Daemon: spectrum frames on the wire — unassigned, small

Follow-up to T4, prerequisite for the live (non-demo) waterfall in T6.
Reference: `plan/tui-waterfall-spec.md` §3 (`SpectrumFrame` contract).

In `hertz-daemon`: each dongle worker computes a decimated FFT snapshot (reuse the
channelized detector's FFT where it already runs; for monitor role run a 1024-pt FFT on
the raw ring at ~10–20 fps) and publishes it on the bus. Serve over WS `/stream` as a new
binary frame type (magic byte distinguishing it from audio frames — extend
`hertz-types/src/wire.rs` with `encode_spectrum_frame`/`decode_spectrum_frame` + tests):
`[u8 0x02][u8 dongle_idx][f64 LE center_hz][f64 LE span_hz][u8 squelch_open][u16 LE n][f32 LE bins...]`
Opt-in via `?spectrum=<dongle|all>` query param (default off — it's ~40–80 KB/s).
Rate-limit to ≤20 fps per dongle regardless of DSP frame rate.

Done: wire round-trip test, mock_e2e extended to assert spectrum frames arrive when
requested and don't when not.
