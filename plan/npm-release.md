# Hertz npm release plan

Copy Lume's setup (`../lume`: `docs/NPM.md`, `npm/lume/`, `scripts/package-cli.cjs`,
`scripts/bump-version.cjs`, `.github/workflows/{bump-version,release}.yml`). The
Lume agent (Magnificent Vole) will review the workflow PR.

## Packages

- Wrapper `@deepbluedynamics/hertz`: `bin` = `hertz` (TUI) and `hertzd` (daemon),
  both small Node shims. `optionalDependencies` pin the five platform packages
  to the exact same version. There is no postinstall step, because Signal K
  installs with `--ignore-scripts`.
- Platform packages `@deepbluedynamics/hertz-{linux-arm64,linux-x64,darwin-arm64,darwin-x64,win32-x64}`
  are generated by `scripts/package-cli.cjs`. Each has `os`/`cpu` set and
  contains `bin/hertz(.exe)`, `bin/hertzd(.exe)` and `bin/manifest.json`
  (target, sha256, glibc_max). Set `gitHead` to the tag's commit.
- Shim: resolve `@deepbluedynamics/hertz-${platform}-${arch}/package.json`, then
  `spawnSync` the binary with `stdio: 'inherit'`, pass signals through and exit
  with the child's status. Print a clear message for a missing or unsupported
  target, including installs with `--omit=optional`.

## hertz-specific

- **Whistle:** done. The crate now lives in `crates/whistle`, so CI can build.
- **RTL-SDR:** already self-contained. `rtl-sdr-rs` is pure Rust and `rusb` is
  built with `features = ["vendored"]`, so libusb is linked statically. Check
  the LGPL obligations of static libusb before publishing. On the Pi, document the
  udev rule and `blacklist dvb_usb_rtl28xxu` (npm can't install them; later this
  could be a HaLOS .deb like Lume's `scripts/build-halos-debs.sh`).
- **Whistle engine and weights:** downloaded at first run from Hugging Face
  (`manylinux2014_aarch64` on the Pi). Boats are often offline, so either bundle
  the engine and `whistle.cact` (17 MB) in the platform package, or pin a sha256
  and fail clearly when offline. Bundling is friendlier.
- Without the Whistle service or Hyperia, hertzd still scans and records. The relay
  and the Whisper double-check are optional.

## Versioning and CI

- One version everywhere. `scripts/bump-version.cjs` updates the workspace
  `Cargo.toml`, `Cargo.lock` and the wrapper's `package.json` and pins.
- `bump-version.yml` (workflow_dispatch: patch|minor|major|X.Y.Z) commits
  `release: vX.Y.Z`, tags and pushes, then calls `release.yml` as a reusable
  workflow. A tag pushed with GITHUB_TOKEN doesn't trigger other workflows.
- `release.yml` jobs, in order: check that the tag, Cargo and package.json
  versions agree; build matrix; package (`npm pack` offline); GitHub release
  with SHA256SUMS; npm publish.
- Publishing uses npm trusted publishing (OIDC: `id-token: write`, Node 22.14,
  npm 11.6.2), with no NPM_TOKEN; provenance is automatic. Platform packages go
  first and the wrapper last. Skip any `name@version` already on npm, publish
  with `npm publish "./npm/$file"` (keep the `./`), and fail at the end with a
  "Not published:" list.

## Gotchas (from Lume)

- Set up a trusted publisher on npmjs.com for each package. Owner, repo,
  workflow file name and environment must match exactly, otherwise npm answers
  E404. Add both `bump-version.yml` and `release.yml`.
- A brand-new package must be published once by hand first: `npm login` in a
  browser with a security key, from a real TTY (EOTP otherwise).
- npm registry lag can cause E409 on a rerun. `gh run rerun` uses the
  workflow as it was at the tag.
- On Windows, a Node caller should spawn the real .exe, not the `.cmd` shim.

## Pi test (later)

`npm i -g @deepbluedynamics/hertz` on the Pi, then add the udev rule and the
blacklist, plug in the dongle and run `hertzd <config> --listen`. Check: dongle
found, audio out, Whistle download or bundle works offline.
